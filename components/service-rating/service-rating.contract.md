# service-rating

يُركّب عبر scripts/feedback_markup.py باستخدام Button وText Input وRating للنجوم. يستخدم textarea أصليًا بتنسيق حقل النص لأن حزمة textarea السابقة كانت مصدرًا معلقًا. اختيارات الأسباب وأزرار الراديو عناصر HTML أصلية. الشكل وحالات النجوم من أصول Figma الأصلية، والإغلاق والنجاح متاحان ضمن الأصول.

قالب HTML مستقل، CSS خاص للمكوّن مع styles/composites/feedback.css، وسلوك مشترك في styles/composites/feedback.js. لكل نسخة معرف فريد وsubject مستقل. يجب تحميل الأنماط الأساسية وButton وText Input وRating وملفات التنسيق المشتركة. يمكن عرض أكثر من نسخة في الصفحة دون تداخل.

الحالات: default، open، pending، error، submitted. الإغلاق وEscape يعيدان التركيز إلى زر الفتح؛ حقل النجوم يستخدم مجموعة radio أصلية من 1 إلى 5 مع أسهم لوحة المفاتيح. الأسباب تتبدل حسب نعم/لا، ويُقبل سبب واحد أو سببان. حقل الجنس اختياري ويبدأ بخيار «أفضّل ألا أقول». لا تُنسخ إلزامية الجنس من موقع الجامعة.

لا توجد إحصاءات مصطنعة: count مع average للخدمة أو percentage للصفحة حقول اختيارية. لا تخزين محلي ولا إرسال افتراضي. بعد تحميل الصفحة، استخدم `PlatformFeedback.setSubmitHandler(element, async payload => ...)` لربط الخادم؛ يجب إعادة true فقط عند تأكيد نجاح الخادم، وأي فشل يحتفظ بالمدخلات ويعرض إعادة المحاولة. تُرسل kind وsubject وcomment مع score أو useful/reasons/gender. values للأسباب فهارس ثابتة تبدأ من صفر لكل اختيار useful.

المعاينة تعرض نتيجة محلية صريحة دون ادعاء الإرسال، ولا تغير المتوسط أو عدد المشاركات. عدم تشغيل JavaScript يعرض رسالة واضحة ويخفي أزرار الإدخال. على الخادم مسؤولية التحقق من البيانات والصلاحيات وتكرار التقييم. الاستدعاء idempotent عبر PlatformFeedback.init(container).
