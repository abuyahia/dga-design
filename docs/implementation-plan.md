# خطة التنفيذ

## الدفعة الأولى — منفذة

1. توثيق الطبقات والمسارات والاعتماد في architecture.md.
2. جرد الموجود والمخطط وتحديد نسخ Link وAccordion للعمل القادم.
3. إصلاح JSON وتوحيد envelope المراجع والتدقيق مع حفظ بيانات المصدر.
4. فحص repository قابل للتشغيل واختبارات regression للأداة، وتسجيل الفجوات دون إخفائها.

## الدفعة الثانية — Tokens وBase، منفذة

تفاصيل التنفيذ والحدود في [foundation.md](foundation.md)، ونتيجة الفحص في `batch-2-result.json`.

1. تصنيف token_not_central إلى توكن مكوّن، اسم Figma، أومتغير runtime داخلي؛ لا تنقل متغيرات مثل fill إلى tokens بصفتها قيم تصميم ثابتة.
2. إعادة استخدام primitive/semantic tokens الحالية، وربط aliases بدل نسخ القيم.
3. نقل التعريفات التصميمية المحلية إلى المصدر المركزي وإزالة fallbacks المخالفة تدريجيًا.
4. تسوية container/breakpoint/focus/z-index policies؛ لا إنشاء tokens إلا لحاجة.
5. تنفيذ ملفات Base الثلاثة مع أمثلة اختبار معزولة في RTL/LTR.
6. مراجعة نتائج strict وإغلاق الفجوات ذات الصلة أوتوثيق استثناء محدد بدليل؛ لا تجاهل تحذيرات جماعيًا.
